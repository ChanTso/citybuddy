## Goal

Add the smallest low-cardinality, purely observational metrics for current verified Agent paths and
the FAQ/model counts required by CB-152, together with an optional Agent trace sink that defaults to
`Noop`. Do not instrument `auth-service` or `commerce-service`.

## In scope

- Define count and duration observations for the Agent operations `knowledge.search`, chat turn,
  PendingAction prepare, clarification, decline, and expiry. Each operation has a bounded outcome
  classification; identifiers, content, and raw dependency/model errors cannot become labels.
- Define separate mapping-cache and answer-cache counters with the bounded terminal outcomes `hit`,
  `miss`, `bypass`, `unavailable`, and `invalid`. Each eligible logical lookup contributes exactly
  one terminal outcome at each cache layer it reaches; replay and internal retry do not add another
  logical lookup outcome. Calculate FAQ hit rate separately for mapping and answer as
  `hit / (hit + miss)`; bypass, unavailable, and invalid are reported but excluded from that
  denominator.
- Record one model-turn decision as `issued` or `avoided`, with a bounded reason, for each eligible
  non-replayed logical turn. Calculate model-call saving as
  `avoided / (avoided + issued)`. Provider retry or fallback does not create another turn decision.
- Record each actual provider attempt by the bounded role `primary`, `fallback`, or `reranker` and a
  bounded outcome. Attempt counters describe outbound attempts and never enter the model-call-saving
  denominator, so fallback and retry cannot double-count an issued/avoided decision.
- Provide an Agent-internal Prometheus text endpoint backed by a custom `CollectorRegistry`. It is
  disabled by default, is absent or returns `404` while disabled, is excluded from public OpenAPI,
  and registers no default process or garbage-collection metrics.
- Provide an Agent-only optional trace sink with a bounded queue, bounded export timeout, zero retry,
  and default `Noop`. Trace enqueue/export failure, timeout, malformed response, and shutdown cannot
  determine business or evaluation success.
- Maintain a machine-readable metric inventory and executable cardinality tests that close the set
  of metric names, units, types, labels, bounded values, and verified Agent producers.
- Exclude user, token, session, turn, trace, order, product, reservation, payment, refund,
  PendingAction arguments, prompt/reply/retrieved content, server-only reasons, credentials, and raw
  errors from all metric labels and trace payloads.

## Acceptance criteria

1. The machine-readable Agent metric inventory is closed and stable: every metric has one name,
   unit, type, bounded label set, bounded unknown/outcome handling, and documented verified producer;
   executable cardinality tests reject additions outside it.
2. Operation count/duration observations cover only `knowledge.search`, chat turn, and PendingAction
   prepare/clarification/decline/expiry, without changing their response, authorization, transaction,
   state, retry, or durable evidence behavior.
3. Mapping and answer FAQ cache hit rates are executable as `hit / (hit + miss)`, and model-call
   saving is executable as `avoided / (avoided + issued)`. Producer matrices prove replay, internal
   retry, bypass, denial, failure, and provider fallback cannot double-count or misclassify either
   formula.
4. Provider-attempt counters represent actual primary, fallback, and reranker outbound attempts with
   bounded outcomes, while remaining separate from the single logical model-turn decision.
5. Metrics are disabled by default. The internal Prometheus endpoint is absent or `404` when
   disabled, is never in public OpenAPI, uses only the custom registry, and exposes no default
   process or garbage-collection collectors when enabled.
6. Tracing defaults to `Noop`; the enabled sink has a bounded queue and timeout and performs zero
   retry. Missing configuration, outage, timeout, malformed export, queue saturation, and shutdown
   leave business responses, state, and evidence unchanged.
7. Metrics and traces contain none of the prohibited identity, business, content, credential, or
   server-only fields. No assertion, evaluation result, retry decision, state transition, or public
   response reads from either observational channel.
8. No Auth or Commerce instrumentation, Agent confirmation/receipt/turn commit, memory, handoff,
   measurement execution, dashboard, or cross-service trace behavior is added.

## Rejection paths

- Reject dynamic identifiers, free text, secrets/private content, unbounded names or values, and raw
  dependency/model errors in metrics or traces.
- Reject ambiguous FAQ/model formulas; replay/retry/fallback double counting; and any result that
  cannot be reconstructed from the closed Agent producer events.
- Reject tracing as a required dependency, trace success as evidence, retry-on-export amplification,
  unbounded queue/timeout behavior, or export failure changing business results.
- Reject introducing Java instrumentation in the name of unified three-service observability,
  including an Auth or Commerce registry, metrics dependency, scrape endpoint, operation producer,
  Micrometer integration, or trace implementation.
- Reject adding Auth or Commerce metrics during CB-152, treating their absence as invalidating a
  performance run, or guessing a first bottleneck when the permitted evidence cannot isolate one;
  the required result in that case is `indeterminate`.
- Reject counters or traces for unimplemented Agent confirmation, receipt Turn commit, memory,
  handoff, or failure-candidate export.

## Out of scope

- `auth-service` metrics, `commerce-service` metrics, Micrometer, Java metrics endpoints, and
  cross-service distributed tracing;
- Prometheus server, Grafana, dashboards, alert routing, SLO policy, production observability
  infrastructure, real-provider telemetry, log aggregation, or deployment;
- Agent successful confirmation/receipt projection/turn commit, memory/PII, handoff, candidate
  export, cart/storefront expansion, demo reset/drills, and load or quality execution.

## Required evidence

- Agent metric inventory and cardinality tests covering names, units, types, labels, bounded values,
  and exact producer coverage;
- mapping/answer FAQ and model-decision/provider-attempt matrices covering hit, miss, bypass,
  unavailable, invalid, issued, avoided, replay, retry, denial, fallback, and dependency failure;
- Agent operation count/duration evidence for `knowledge.search`, chat turn, and PendingAction
  prepare/clarification/decline/expiry;
- disabled/absent and enabled Agent scrape-endpoint tests, including public-OpenAPI exclusion, custom
  registry isolation, and absence of default process/garbage-collection collectors;
- default-`Noop`, enabled fake sink, queue saturation, timeout, outage, malformed-export, shutdown,
  and zero-retry trace tests;
- privacy, redaction, secret, prohibited-field, business-equivalence, and no-truth-reader evidence;
- real retrieval and evaluation integration evidence proving metrics and tracing do not alter
  existing behavior;
- complete-diff self-review, fresh independent review, and final repository checks.
