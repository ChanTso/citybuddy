## Goal

Provide bounded, repeatable reset, demo, and controlled fault-drill scripts for the verified
portfolio paths only, producing a clean operator-visible result without inventing Agent confirmation,
receipt, memory, handoff, or export behavior.

## In scope

- Add one documented reset/setup path that starts from the supported local topology and establishes
  the exact identities, products, activities, orders/payments/refunds, FAQ/RAG fixtures, support
  sessions, and PendingAction prepare fixtures needed by the demo and CB-152.
- Add an ordered demonstration script for identity, catalog, standard ordering/seckill reservation
  and status, mock payment/refund, RAG, chat, and PendingAction prepare/decline/expiry.
- Add repeatable, phase-bound fault drills only where existing verified boundaries already define a
  safe failure: authentication/ownership denial, catalog/cache dependency behavior, seckill
  idempotency/status convergence, payment/refund replay or rejection, RAG insufficiency/unavailability,
  chat dependency failure, and PendingAction prepare/decline/expiry non-success behavior.
- Make every destructive reset explicitly evaluation/local-only, bounded to a generated sandbox or
  documented fixture scope, preflight its target, and fail closed before touching ambiguous data.
- Record environment, seed/dataset identity, commands, expected observations, cleanup, and a
  machine-readable pass/fail summary suitable for CB-152 setup. Preserve server truth as authority.

## Acceptance criteria

1. A clean supported local environment can run reset/setup, the complete verified-path demo, and
   cleanup using documented commands with deterministic fixture identifiers and bounded timeouts.
2. Repeating reset or any demo step is idempotent or returns a documented stable conflict; it never
   duplicates durable orders, payments, refunds, reservation effects, support turns, or PendingAction
   local closure.
3. Every fault drill identifies the exact operation phase and trigger, proves the expected public
   classification and durable owner truth, then removes the fault and proves normal behavior resumes.
4. Reset and cleanup reject missing/production profiles, ambiguous scope, unknown fixture versions,
   active unrelated data, or absent confirmation guards; repository-wide or host-wide deletion is
   impossible through the script interface.
5. Demo output distinguishes reservation from order, payment from refund, retrieval evidence from
   model prose, and Commerce PendingAction authority from Agent-local prepare/decline/expiry state.
6. No script calls or simulates Agent successful confirmation, Agent ActionReceipt/turn commit,
   MemoryPacker summary, handoff, or failure-candidate export.
7. Commands, environment, dataset, expected results, first failure, and cleanup status are recorded
   without credentials, private data, or internal-only evidence leakage.

## Rejection paths

- Reject broad cleanup targets, unresolved variables/globs, production profiles, destructive fallback,
  silent partial reset, and fixture reuse across unrelated runs.
- Reject sleeps without bounded readiness/state checks, retries that hide failure, and fault rules not
  bound to the exact method/target/attempt/phase they claim to exercise.
- Reject demos that infer success from HTTP status, cache/trace data, model prose, or Redis instead of
  the verified authoritative state.
- Reject confirmation/receipt, memory, handoff, candidate-export, or generalized recovery-scanner
  demonstrations.

## Out of scope

- production data administration, backup/restore, deployment, chaos platform, security penetration
  testing, dashboards, real-provider access, or generalized recovery automation;
- Agent successful confirmation/receipt/turn commit, memory/PII, handoff, failure export, and
  measurement/report claims owned by no current path before CB-152.

## Required evidence

- clean-start and repeat-run transcripts for setup, every demo path, and cleanup;
- exact durable-state and public-result assertions for identity, catalog, ordering/seckill,
  payment/refund, RAG, chat, and PendingAction prepare/decline/expiry;
- phase-bound fault-drill evidence with recovery and no hidden skip/retry;
- destructive-scope rejection tests for profile, target, fixture version, and unrelated data;
- secret/private-data scan plus complete-diff self-review, fresh independent review, and final
  repository checks.
