Agent refund confirmation, end to end against the real local topology.

Produced by bench/agent/check_action_confirmation.py running inside the bench network
namespace, against services started by bench/agent/setup_agent_bench.sh with
AGENT_BENCH_USERS=8. auth-service, commerce-service, MySQL and Elasticsearch are the real
local containers; the model provider is scripts/fake_litellm_server.py.

One entry takes the JSON path and one takes the SSE path. Each prepares a refund against
an order it owns, then confirms it in a second turn. The JSON entry additionally has its
durable state put back into the exact shape a lost commerce response leaves - reference
CONFIRMING, no projection, no confirmation turn - and is then confirmed again with a
fresh idempotency key, which reaches commerce a second time.
